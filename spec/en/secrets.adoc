= Secrets
include::_fpsot-terms.adoc[]

These rules set how an {abbr-fpsot-first} project keeps its secrets out of its code and its releases.
A secret is any value that grants access, such as a password, a private key or a token.

== Where secrets never go

[[SEC-020]]
*SEC-020.* A secret MUST NOT appear in a repository, its history, a container image or a release artifact.
It MUST NOT appear in a log, a test report or an error message either.
A product MUST read each secret at run time, from its environment or from a secret store.
A product MUST NOT ship with a default password or a default key.
People copy repositories and images far and wide, and nobody can take back a secret in them.
Test fixtures follow TST-050 and TST-054, and hold no real credential.

[[SEC-021]]
*SEC-021.* Each repository MUST turn on a scan that blocks a push when the push contains a secret.
A person MAY bypass a block only for a value that is not a secret, with the reason recorded.
A secret that never reaches the server does not need a rotation.
Examples of this capability are GitHub push protection and a pre-receive hook on a self-hosted forge.

== When a secret leaks

[[SEC-022]]
*SEC-022.* The owner of a leaked secret MUST revoke it at once.
A secret leaks when it reaches any place outside its store, such as a repository or a log.
The owner MUST then issue a new secret and check the logs of the system for its use.
A rewrite of the history MUST NOT count as a fix, because copies of the old history remain.
The owner MUST report the leak under SEC-040 when the secret protects a system that other people use.
A leaked secret stays valid until someone revokes it.

== Rotation and scope

[[SEC-023]]
*SEC-023.* Each secret MUST have a named owner and a rotation period.
The owner MUST rotate it at least once a year, and at once when a person with access leaves.
A project SHOULD prefer credentials that expire within hours, such as the job tokens of a {abbr-ci-first} service.
A short life limits the harm of a secret that leaks without anyone noticing.

[[SEC-024]]
*SEC-024.* The {abbr-ci} service MUST keep each secret in its own secret store, scoped to the jobs that need it.
A job MUST receive only the permissions it needs, and the default permissions of each workflow MUST allow reading only.
A secret MUST NOT reach a job that runs code from a pull request of an outside fork.
A release secret SHOULD sit in a protected environment that needs the approval of a maintainer.
A job that runs code from a stranger with access to a secret gives that secret to the stranger.
